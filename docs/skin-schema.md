# Skin documents, schema 1

A skin document is a whole Vela skin as data: JSON that Ether serves and every client
draws through one compiled renderer, the **doc engine**. Nothing in a document executes:
it is a tree of typed nodes, CSS-like styles, references to a fixed binding vocabulary,
conditions, named motion presets and assets. Types: `protocol/v0/skin.ts`. Renderer:
`client/renderer/levels.contract`, generated by `tools/renderer.ts`. Resolver:
`client/src/skin/index.ts`. Engine slots: `client/skins/doc/slots.contract`. The
fidelity proof, cinematic as a document: `protocol/v0/fixtures/skins/cinematic.ts`.

## Why it is shaped like this (Exact, pinned)

| Exact rule | Consequence |
| --- | --- |
| Shapes are finite and nonrecursive (`contract-grammar.md:3020`); a component cannot use itself (`syntax-inline-depth`) | The renderer is 12 generated levels `L1..L12` over shapes `N1..N12`. A document nests at most 12 boxes deep; the resolver refuses deeper ones. |
| A component is inlined at every call site | Each level calls the next from exactly one place: one generic container; only leaves (text, image, icon, widgets) branch. A slot draws its tree from one call site. |
| `:hover`/`:focus` rows are literals or token names (`lower-state-literal`) | Hover, press and group hover are CSS the resolver writes (the document's `css`, injected by vela-theme) on the nodes' `data-vs`/`data-vg`/`data-vf`: a pointer over the page runs no script. Focus looks (keyboard focus, a group's focus) are the renderer's own state, since parent-from-child CSS (`:has`) is missing on the TV browsers. |
| An action receives every prop and inject of its component as hidden arguments, type-checked deeply on each call | Renderer components declare no actions that read their props: events go to the app's own actions (`client/skins/doc/members.contract`) with a few strings, so an event never re-checks a subtree or the page's models. |
| Every element with `color-scheme` is a colour boundary that Exact's modes pass walks after every commit | `color-scheme` is set only on a tree's root box (the shell's or a route's); the resolver refuses it elsewhere. |
| Exact probes every element that binds a layout transition or an exit before every commit | A route's nodes may take `layoutTransition` or `exit` only within 6 levels (the resolver refuses deeper ones); the shell's anywhere. A route's deep levels (cards, posters, captions) draw through a box without them. |
| Computed `border`/`flex` must be longhands (`lower-css-shorthand`, `lower-attr-type`) | Write the shorthands; the resolver splits them. |
| Number rows (`opacity`, `order`, `flex-grow`, `flex-shrink`, `font-weight`, `line-clamp`, `scale`) take numbers | Write them as strings; the resolver converts and resolves `font-weight` inheritance down the tree. |
| A bound `position` on a clipping box is `relative`, `absolute` or `sticky` | `fixed` and `static` are not offered; anything else is `relative`. |
| An empty bound row resets to the default, it does not inherit | The resolver writes `inherit` for unset inherited rows (colour, font, text). |
| Keyframes are declared at compile time | Motion is a preset library (below) plus per-document duration, delay, easing, fill, iterations, direction and a reduced-motion alternative. |
| Expressions nest at most 64 deep | The vocabulary resolver is split into chunks. |

## Document

```ts
{ schema: 1, renderer: 1, id, name, version, tagline?, preview?, swatches,
  tokens?: { name: css },                 // `$name` in any style value
  strings?: { en: { key: text }, fr: … },  // `{s:key}` in any template, by the viewer's locale
  fonts?: { name: { family, files[], sizeAdjust? } },
  motion?: { name: MotionPreset },
  templates?: { name: Node },             // `{ type: "use", template: name }`, inlined
  slots: { shell?: Node, home?: Node },    // a slot left out uses cinematic's compiled one
  routes: { title?: Node, … },             // a route drawn whole by the route view (one call site)
  detail?: { wide?, small?: "fullscreen" | "modal" | "stack" },
  live?: { home?: boolean } }
```

Colour values may be CSS, a Tamber token name (`surface.page`, `cinematic.glass`) or
`var(--token.name)` inside gradients and shadows, as Contract rows accept them.

`renderer` is the lowest renderer version the document needs; a client draws it only when
its `RENDERER_VERSION` is at least that (`docs/distribution.md`, "Skin document
compatibility"), and otherwise falls back to the built-in cinematic document.

## Nodes

Every node takes `style` (CSS name to value), `small` (under 640 px) and `wide` (from
1200 px) overrides, `hover`, `focus`, `group` + `groupHover`, `when` (all must hold),
`motion` + `stagger {step, cap}`, `role`, `label`, `level`, `testId`.

| Type | Fields | Draws |
| --- | --- | --- |
| `box` | `children`, `press {action, arg}` | One flex/grid/block container: a flex **column** unless its style says otherwise (`display: flex` alone keeps the column; write `flex-direction: row` for a row, unlike CSS's default). With `press` it gains a full-size transparent button carrying `label` (keyboard and screen readers) over its content. |
| `text` | `text` (template) | Text. |
| `image` | `src` (template), `alt`, `fade` | An image: a vocabulary URL (`{card.poster}`), an app asset (`assets/grain.svg`) or the document's own assets under `/vela/v0/appearance/`. `fade` reveals it once loaded. |
| `icon` | `symbol` | A platform symbol (`search`, `play-fill`, `checkmark`). |
| `repeat` | `over`, `limit`, `item` | `item` once per element of `home.rows`, `row.items`, `home.heroes`, `home.hero` (the current one) or `nav.destinations`; the element becomes the binding context and its position `{index}`. A repeat draws no box of its own: its `when` applies to each item, its `style` and variants do not (style the `item`). |
| `use` | `template` | A template, inlined; the use node's style, conditions and motion wrap it. |
| `slot` | `slot`, `style`, `inner` | Where the foundation's content goes among a slot's top-level nodes: `children` (the route a shell wraps), `searchField` (home). |
| `widget` | `widget`, `params` | A compiled interactive part: `install` (`params.action` install/update), `observe` (`params.receipt`: the visibility receipt). |

Templates are text with `{key}` holes. Keys: `card.*` and `hero.*` (`id`, `kind`, `name`,
`summary`, `facts`, `factsLine`, `yearLabel`, `rating`, `progressLabel`, `poster`,
`backdrop`, `logo`, `accent`, `receipt`, `kindId`; card also `played`, `progressPct`,
`hasProgress`, `label`), `row.id/name/presentation`, `heroAct.reasonLabel/actionLabel/
actionDetail/action/targetId/playable/progressPct/hasProgress`, `dest.id/name/kind/on`,
`env.viewer/viewerInitial/section/query/small/still/searching/canLive/heroCount/
heroIndex/rotating/rowCount`, `index`, `index.label`, `index.current`, `flag:<name>`.
Detail (route `title`): `detail.*` (`id`, `kind`, `kindLabel`, `kindId`, `name`, `summary`,
`facts`, `factsLine`, `poster`, `backdrop`, `logo`, `accent`, `receipt`, `canPlay`, `playLabel`,
`hasResume`, `resumePct`, `hasSeasons`, `hasEpisodes`, `hasCast`, `crewLine`, `hasExtras`,
`hasRelated`, `selectedSeason`); collections `detail.seasons` and `detail.episodes` and
`detail.upNext` (card context, plus `season.on`, `season.pick`, `episode.numberTitle`,
`episode.upNextLabel`, `episode.playLabel`), `detail.extras` (`extra.*`), `detail.cast`
(`person.name/role/portrait/initials`), `detail.mediaFacts` (`fact.text`), `detail.related`
(row context). `env.route`, `env.load` (`loading`, `failed`, `ready`), `env.entry` (the stack
entry id: name a route's scroll box `{env.route}-scroll-{env.entry}` with `id` so navigation
restores it), `env.tv` (viewport from 1600 px), `card.episodeNumberLabel`, `card.durationLabel`.

Bindable style rows (a template in the value): `width`, `background-color`,
`background-image`, `color`, `opacity`, `translate`.

Conditions: `{ test: key, is?: "set" | "eq" | "ne" | "gt" | "lt", value?, not? }`.
`set` means non-empty, not `false`, not `0`.

Actions: shell `home`, `search`, `live`, `library {dest.id}`, `toggle/open/close <flag>`,
`openPicker`, `signOut`; home `select {card.kindId}`, `play {hero.id}`,
`pickHero {index}`, `toggle <flag>`; routes `select`, `play {card.id | detail.id}`,
`playExtra {extra.id}`, `back`, `toggle`. A season tab selects with `select {season.pick}`. Flags are the slot's own UI state (a menu open).

## Live home

A document may make home itself a live surface: `live: { home: true }`. Home then holds
the guide's listings and minute clock, and the same single preview tile the guide uses
(one muted ambient session; released when home is not the visible route, the tab is
hidden, a query is open or full watch starts; Save-Data and reduced motion wait for
`tuneIn`; the viewer's current channel is remembered). Without it, nothing live loads on
home.

| Vocabulary | Meaning |
| --- | --- |
| `live.channels`, `live.favorites` | Collections: the guide's channels in its order (favourites first), and the favourites alone. Use `limit` on large lineups. |
| `ch.*` | `id`, `number`, `name`, `logo`, `group`, `favorite`, `now`, `next`, `nowProgress` (0-100), `nowRemaining`, `nextLabel`, `nowArt`, `nowEpisode`, `nowGenre`, `tuned` (it is on the monitor). |
| `tile.*` | The monitor: `state` (`off`, `tune-in`, `connecting`, `playing`, `unavailable`), `muted`, `zapping` (the number being dialled while flicking), and the tuned channel's `channelId`, `channelName`, `channelNumber`, `logo`, `now`, `next`, `nowProgress`, `nowRemaining`, `nextLabel`, `nowArt`, `nowEpisode`, `nowGenre`. |
| `env.clock`, `env.liveReady`, `env.channelCount`, `env.favoriteCount` | The guide's minute clock (locale-formatted; shell and home), listings loaded, lineup and favourites sizes. |
| widget `liveTile` | The tile's picture, filling its box (top three levels only). The document draws every state, bug and caption over it from `tile.*`. |
| actions | `watch {ch.id}` full-screen watch (after the tile's stop), `preview {ch.id}` put a channel on the monitor, `zap {1|-1}` flick the monitor (it retunes once the viewer pauses), `tuneIn`, `unmute` (toggles), `guide` open the full guide. |

ChannelUp/ChannelDown keys flick the monitor on a live home, as they flick full watch.

## Motion

`{ keyframes, duration, delay?, easing?, fill?, iterations?, direction?, still? }`.
Keyframes: `rise`, `dissolve`, `vanish`, `pop`, `open`, `expose`, `drift`, `fill`,
`shimmer`, `spin`, `breathe`, `glow`, `float`, `bounce`, `twinkle`, `slideUp`, `slideIn`,
`zoom`, `wiggle`, `auroraA/B/C`, `scan`, `sway`, `sheen`, `tick`, or `none`. Under reduced motion the renderer
plays `still` (default: none). `stagger {step, cap}` adds `min(index, cap) * step` ms.
Bespoke motion (a mascot's walk, sparkles) belongs in animated SVG assets.

## Fonts

`fonts: { name: { family, files: [{ url, weight, style }], sizeAdjust? } }`: same-origin
woff2/woff/ttf/otf under `/vela/v0/appearance/`, at most 8 families of 4 files. The client
registers each under its `family`, so styles name it as usual
(`font-family: "Barlow Condensed", sans-serif`). A pressable box with a `focus` or
`groupHover` overlay draws its own focus indicator: its press button has no outline.

## Limits

512 KiB per document, 4,000 nodes after templates are inlined, depth 12, style
properties and keys from the lists above only. A value containing `url(`,
`expression(`, `javascript:`, `@import`, `;`, braces, angle brackets or a backslash is
refused (document assets go through `image`). Unknown actions, collections, widgets,
keyframes, templates and properties are refused with their name.

## Renderer 4

Requests from the converters (Index, Jelly Twin, Marquee, Mochi, Cinematic) and the new
skins, merged into one set. The bar is a pixel-identical match, so each is taken.
Renderer 3 is the live home above; a document using anything here names `renderer: 4`.

**Node features**
- `states: [{ when: Condition[], style: Style, hover?, focus?, groupHover?, groupFocus? }]` (up to 16): the first
  state whose conditions hold replaces `style` (viewport variants still apply over it), on the same element,
  so transitions run (dot widths, padding while searching, on/off pills). A state's overlays replace the
  node's own while that state holds (a state without one keeps the node's), and an overlay written only
  inside states still counts: a pressable node's focus look in any state shows under keyboard and TV focus
  while that state holds, and suppresses the platform ring as a node-level `focus` does (unless it says
  `outline: auto`).
- `layoutTransition: "300ms ease-out"`, `exit: "<motion>"`. `sharedElement` is accepted and ignored for
  now: Exact runs every commit inside a view transition while any element binds one, and a
  press during a transition landed on <html> (every click lost on a page that used it).
- `below: { "<px>": Style }` and `above: { "<px>": Style }`: viewport overrides at the
  document's own breakpoints (`small`/`wide` remain as 640/1200 shorthands).
- Icons from the document: `{ type: "icon", paths: ["<SVG path data>", …], viewBox?, fillRule? }`
  (up to 8 paths) painted in `currentColor`, so they follow colour, hover and states like a platform symbol.
- Document keyframes: `keyframes: { name: { "0%": { opacity?, translate?, scale?, rotate? }, … } }`
  (numbers and px/% only); a motion preset names one as `keyframes: "doc:<name>"`.
- Focus: `focus` is keyboard focus (focus-visible); `groupFocus` beside `groupHover`; a group's
  focus includes focus inside it.
- Press: `press: { action, arg?, focus?: "<id>" }`; `disabled: Condition[]` with a
  `disabled` style overlay; `a11y: { expanded?, selected?, current?, pressed?: Condition[],
  haspopup?, controls?, title?: Template, role? }` on the press button.
- `escape: "<flag>"` on a node: Escape (anywhere on the page) clears the innermost such node's open
  flags and returns focus to `returnFocus` (a literal id).
- Flags named `keep-…` survive navigation actions; shell `reset` clears all others.
  Shell `only <flag>` opens that flag alone (closing the other non-keep flags); pressed again it closes.
- Home's `nav.destinations` (and `dest.*`, `env.libraryCount`, `env.hasLiveLibrary`) list the libraries
  on home too, with actions `library {dest.id}` (a live library opens Live) and `live`.
- Boxes are never Tab stops (Escape handling no longer makes them focusable); focus goes to press buttons.
- The slot box takes every style row (position, z-index, background, backdrop…).
- Rows: `color-scheme`, `column-gap`, `row-gap`, `scroll-behavior`, `scroll-padding-left`,
  `border-left-width/color`. Under reduced motion overlays also drop `rotate` and `animation`.
- Fonts: `weight` may be a range (`"300 700"`) for variable faces.
- A text node's `overflow-x: hidden` and `text-overflow: ellipsis` apply to its characters,
  so a one-line ellipsis draws "…".
- A route's root box takes every style row and a position: a full-bleed page is
  `position: absolute` with `inset: 0`, or `width`/`height: 100%`.

**Vocabulary**
`*.seed` (id length; `person.seed` name length) and `*.nameLength` for card/hero/row/person/dest/
detail/extra; `card.seasonNumber`, `card.episodeNumber`, `card.seasonNumberLabel`,
`card.unwatched`; `hero.label`, `hero.genresLine`, `hero.metaLine`; collections `hero.genres`,
`detail.genres` (`genre.text`), `detail.trailers`, `detail.crew` (`person.*`);
`detail.yearLabel/year/rating/played/durationLabel/resumePosition/seasonCount/seasonName/
hasProgress/progressPct/seasonPending/genresLine/crewLineComma`; `row.landscape`, `row.resume`,
`row.previewOnFocus`, `row.loadingMore`, `row.hasMore`; `dest.backdrop`; `env.width`,
`env.skinCount`, `env.libraryCount`, `env.hasLiveLibrary`, `env.homeMoreLoading`,
`env.homeHasMore`, `env.clock`; `detail.hasMediaFacts` beside the other `detail.has*`. `detail.nameLength`; `env.canRetry` with the `retry` action (a failed route asks again).

## Renderer 5

- `detail.trailerId`, `detail.trailerReady` (press `playExtra {detail.trailerId}`), `card.genresComma`.
- `detail: { from?: px, small, wide, split?: px }`: below `from` (default 640) the title page
  takes `small`, from it `wide`, and home stays beside it as a pane `split` px wide (none by default).
- A colour row may name a theme token bare (`border: 1px solid cinematic.glass-edge`), as `var(--cinematic.glass-edge)`.
- The press layer over a pressable box is transparent in every state: a document draws its own
  hover and pressed looks (a compiled button's hover fill is `var(--exact-quaternary-fill)`).

## Renderer 6

- Theme tokens Tamber folds (one value, no axis: `brand.warm`, `index.page`, …) resolve to their
  value, so `var(--brand.warm)` and bare `brand.warm` draw the token's colour.
- A slot's root box and its holder take `states`, `small`/`wide` and `below`/`above`, live on `env.width`.
- Home without a `searchField` slot node draws no search field.
- A top-level `repeat` keeps its place among its siblings.
- Smaller engine: environment-only vocabulary is bound once per slot, not per node.

## Renderer 7

- **searchInput** widget (within 3 levels of home or of the shell): the bare input (`id`
  `vela-search`, test id `search`) on the foundation's query. `params`: `placeholder`, `label`
  (accessible name, default the placeholder), `placeholderColor`; the node's style sets the text's
  `color`, `font-*`, `letter-spacing`, `text-align`. The document draws the field around it.
  `env.searchFocused` while it has focus; actions `clearSearch` and `focusSearch` (or
  `press.focus: "vela-search"`); Escape with a query clears it. Leave out home's `searchField`
  slot node and the foundation draws no field of its own.
- **sentinel** widget (within 6 levels): `params.on: "row"` (inside a row: its next page) or
  `"home"` (home's next rows). It fills its box; place it in the end cell you draw, and show
  `row.loadingMore` / `env.homeMoreLoading` around it.
- **pager** on a box inside a home row: `pager: { inset?: px, peek?: px (60) }` makes that box
  the row's sideways scroller (give it `overflow-x: auto`, `scrollbar-width: none`). Actions
  `pageNext` / `pagePrev` with arg `{row.id}` scroll it by max(200, home width - 2 x inset - peek);
  `pager.overflows`, `pager.atStart`, `pager.atEnd` for the arrows.

## Renderer 8

- **Keyboard order follows the document**: a slot's holder (the shell's route, home's search
  field) is drawn at its node's position, so Tab reaches nodes in document order.
- **Focus ring**: a press button and the search input show Exact's (the platform's) focus ring
  unless the style in force says `outline: none` (a node with a `focus`/`groupFocus` overlay
  suppresses it, as before; `outline: auto` in the overlay keeps the ring with it). Only `none` and
  `auto` are accepted: the platform draws the ring itself.
- **Control states**: a pressable box shows Exact's hover wash under its content (as a compiled
  button does), unless its style has a background image, it has its own `hover` overlay (an
  authored hover replaces the wash, as an authored `:hover` does in Exact; the pressed state
  still applies), or it sets `controlStates: false` (no wash and no pressed look).
- **searchInput** takes its node's padding (the input is the padded box, so the ring hugs it).
- **traits**: `{ barMask?: bool, panSections?: bool }`: home fades under a floating bar; home,
  libraries and Live TV pan sideways between sections (unset: the doc engine's).
- **status: true** (document): its pages draw their own loading and failure states. Home is
  then drawn while it loads (`env.load` = `loading`, no home models) or fails (`failed`, with
  `env.canRetry` and the `retry` action); a title page always gets its states (`env.load`).
  Without it, the foundation's status screen shows while home loads or fails.
- **detail.frame**: a framed title page's surround, drawn by the route frame over home:
  `{ scrim?: colour (media.overlay), blur?: 'blur(18px) saturate(1.1)', flat?: true }`.

**The page call site.** Home and every route a document draws are drawn by one route view
(Exact copies a component per call site): home is the `home` route (`slots.home`, or
`routes.home`), its `searchField` slot node the holder for the foundation's search field. A
framed title page's scrim and blur belong to the route frame (the doc engine's traits), not
to the document's title root: a route is its own backdrop root, so a blur inside it cannot see
home beneath.

## Renderer 9: library pages

`routes.library` draws every library section of home (they pan beside home as before, one
route view for all). Its environment: `library.id/name/kind/backdrop`, `library.sort`,
`library.direction`, `library.sortLabel`, `library.canFlip`, `library.kindFilter`,
`library.genreFilter`, `library.playedFilter`, `library.favoriteFilter`, `library.year`,
`library.canYear/canPlayed/canFavorite`, `library.more`, `library.itemCount`,
`env.libraryLoading`, `env.libraryMoreLoading`; `env.load` is `loading`/`failed` until the
page's first answer (with `status: true` semantics: draw them). Collections: `library.items`
(cards, `card.*`), `library.kinds`, `library.genres`, `library.sorts` (`opt.id`, `opt.label`,
`opt.of`, `opt.on`). Actions: `librarySort {opt.id}` (keeps the direction when the option has
it), `librarySortFlip`, `libraryFilter "kind|{opt.id}"` (`genre|…`, `played|true`/`false`/``,
`favorite|true`/``), `select` for a title; widget `sentinel` with `on: "library"` loads more.
Without `routes.library` the foundation's library page shows.

## Renderer 10

- `library.kindCount`, `library.genreCount`, `library.sortCount`; action `libraryMore`.
- **select** widget: the platform's select over `params.options` (`library.genres`,
  `library.sorts`, `library.kinds`), its value the current filter or sort; on change it runs
  `params.action` with `params.arg` (`{value}` is the chosen id, e.g. `genre|{value}`).
  `library.played` takes `params.choices`: `"|Any status;false|Unwatched;true|Watched"`
  (value|label pairs; labels may be `{s:key}`).
  `params.none` adds a leading empty option (e.g. "Any genre"); `params.label` names it. The
  node's style sets its height, padding, border, radius, ground, ink and font.
- Fixes: the platform focus ring is no longer overridden by an empty bound outline (`outline:
  auto` works); the control hover wash follows the page's colour scheme (Exact's variable).

## Renderer 11

- **routes.auth**: the signed-out page (sign-in, connecting, offline, quick connect), drawn
  by the route view in home's place. `env.auth` is `offline`, `connecting`, `redeeming`,
  `signin` or `quick`; `signin.error`, `signin.busy`, `signin.canPassword`, `signin.canQuick`,
  `quick.code`, `quick.expires`, `quick.error`. Widget `textInput` (`params.field`
  `username` | `password`, `placeholder`, `label`, `placeholderColor`; the node style styles
  the field; Enter signs in). Actions `signIn`, `startQuick`, `cancelQuick`. A Plex server's
  sign-in stays the foundation's Connect page.
- **traits** also take `page` and `ink` (colours behind every screen) and `splashOnPaper`, so a
  cold start and the launch splash wear the document.
- **states** may carry a `label`: the press button's name while that state holds (one node can
  flip Ascending/Descending and keep its animation).
- Route flag actions `open`, `close`, `only`, `reset` (as the shell's).
- `escape` acts only while one of its flags is open and may name several (`"menu drawer"`), so it
  can sit on a whole bar; a pressable box's `id` is its press button's, so `returnFocus` and
  `press.focus` land on the control. Route action `home`.
- **Pressed**: a pressable box with control states shows Exact's pressed state while held: the
  whole box at .65 opacity (its ground, ring and content; a hover ground stays), with or without a
  ground of its own. An `active` overlay replaces it (author over platform), as a bound opacity or a `hover`
  opacity does.
- **Focus ring**: no inline outline unless the node suppresses the ring (`outline: none`, or a
  focus/groupFocus overlay without `outline: auto`), so Exact's own focus-visible ring is
  drawn exactly as on a compiled button.
- Widget `yearInput` (library pages): the number field on `library.year`; changing it runs
  `libraryFilter year|…`. `a11y.checked` (aria-checked) for menu item radios and checkboxes.
- Row `corner-shape` (e.g. `superellipse(1.6)`, Exact's control curve).
- `sharedElement` belongs on a leaf box without press (an indicator: underline, chip): it is drawn
  by a light element with position, inset, size, radius, ground, shadow, opacity, transform and
  transition rows.
- A group's `groupHover`/`groupFocus` style its descendants, never the group node itself (use
  `hover`/`focus` there).

## Renderer 13: collection pages

`routes.collection` draws a collection (a box set, a folder, a playlist) pushed over home, on
the page colour (draw your own back: press `back`). `collection.name`, `collection.more`,
`collection.complete`, `collection.itemCount`, `env.collectionMoreLoading`; `env.load`
`loading`/`failed` until its first answer (`retry` asks again); collection `collection.items`
(cards, `card.*`, `select` to open one); action `collectionMore` and `sentinel` with
`on: "collection"` load more. Without `routes.collection` the foundation's page shows.
Also: a fully transparent ground (`transparent`, `#rrggbb00`, `rgba(…, 0)`) counts as no ground,
so a pressed control dims its content as a compiled button does.

## Renderer 15: the Vela base

Every skin is a document (build plan, decision 7), and every document draws on top of the **Vela
base** (client/src/skin/base.ts): built-in slots and routes for every surface, styled from the
document's `ui` block. A document draws what it wants to own and inherits the rest.

- **Inheritance**: a slot or route the document defines replaces the base's (home counts whether it
  is `slots.home` or `routes.home`). Templates, motion, keyframes, fonts, tokens and strings merge by
  name, the document's winning; the base's names start with `vela` (`velaCard`, `velaRow`), so a
  document that defines `velaCard` restyles the base's lanes on purpose. Home's `status` and
  `traits.barMask` belong to whoever draws home, `detail` to whoever draws the title page. `slots` is
  optional: a document that only sets its look (`ui`, `traits`) inherits every surface.
- **`ui`**: the base's look, as values: `page`, `raised`, `ink`, `inkSecondary`, `inkQuiet`,
  `inkInverse`, `accent`, `onAccent`, `control`, `controlHover`, `glass`, `glassEdge`,
  `glassEdgeStrong`, `popover`, `scrim`, `track`, `trackStrong`, `focusHalo`, `shadow`, `skeleton`,
  `skeletonLight`, `alert`, `live` (colours), `font`, `fontDisplay` (font stacks), `radiusControl`,
  `radiusCard`, `radiusPanel` (px numbers). A key left out takes Cinematic's value
  (client/src/skin/ui-defaults.ts). Any style may read one as `$ui.<name>` (a radius reads as px).
- **Client strings**: `{t:ui.signIn}` in any template is the app's own string in the viewer's
  locale. A string's placeholders bind to the vocabulary: `{t:secure.body|origin=signin.secureOrigin}`.
  A document's own text stays `{s:key}`.
- `env.skinName`: the document's name.

These are resolver features: whatever renderer draws the resolved document gets them. The version
number 14 went to the Exact renderer's arrow-key focus, which is held on a branch; main skips it.

### Search (`routes.search`)

Search is drawn in home's view, after home's nodes, while a query is open: the search field (home's
holder) stays put and focused as the answers arrive below it. Home's own nodes step aside with
`env.searching`. The Vela base draws search for a document that does not.

| Vocabulary | Meaning |
| --- | --- |
| `env.search` | The title lane: `loading`, `failed`, `ready` (empty with no query). |
| `search.titleCount`, `search.descriptiveCount`, `search.aiCount` | How many titles each lane shows (the title lane none while it loads or failed). |
| `search.describing` | The query reads as a description (several words, descriptive search on): an empty answer is about the mood, not the name. |
| `search.descriptiveState`, `search.canRetry` | The descriptive lane: `off`, `loading`, `failed` (it keeps what it found), `ready`; whether `retryDescriptive` may run. |
| `search.aiState` | Discovery: `off`, `running` (its partial answer shows), `failed`, `complete`. |
| `search.onNowCount`, `search.comingUpCount` | Live hits: channels and programmes airing, and programmes coming up. |
| `hit.*` | A live hit: `id`, `kind` (`channel`, `programme`), `ref` (for `openHit`), `name`, `channelName`, `channelNumber`, `logo`, `artwork`, `episode`, `live`, `progressPct`, `detail` (localized: channel and until when), `chip` (when it starts), `navigable`. |
| collections | `search.titles`, `search.descriptive`, `search.ai` (cards, `card.*`), `search.onNow`, `search.comingUp` (`hit.*`). |
| actions | `select {card.kindId}`, `openHit {hit.ref}` (a channel's page, or a programme: watch it if airing), `retryDescriptive`. |

### The style matrix

Skins draw on React Native as well as the web (docs/rn-migration.md, "Style matrix"). `bun tools/skin.ts
check <document>` refuses the rows native cannot draw (`-webkit-text-stroke`, `position: fixed` or
`static`, `position: sticky` anywhere but on a direct child of a route's root or of a vertical scroll box,
`box-sizing: content-box`, `display: block`, `inline` or `contents`, several text shadows,
`mask-image: url()`, grid placement) and notes the approximated ones (`backdrop-filter`, gradient
`mask-image`, grid columns, `filter`, `corner-shape`, scroll snapping, and allowed `sticky`, which native
pins at the top of its scroll view, ignoring a non-zero `top`). The web still draws a refused
row, with a console warning naming it.
