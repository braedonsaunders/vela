# WebGPU Player review

Status: historical research notes. Vela subsequently adopted the MIT standalone engine at a newer reviewed pin; see [the implementation and measured qualification](playback-engine.md#first-original-file-native-view-milestone). The Jellyfin plugin is not used.

**Recommendation:** Keep Vela’s native `<video>` + MSE/ManagedMediaSource path as the default for Ether HLS/CMAF. Treat WebCodecs + WebGPU as a separately qualified, optional path for cases where native playback cannot provide acceptable HDR-to-SDR rendering or decode a needed codec. The independent player’s custom path currently supports direct-play VOD, **not HLS, DASH, live streams, or server transcodes**, so it is not a drop-in replacement for Vela’s pipeline. [formats.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/formats.md)

**Architecture and useful details**

- The host owns controls and playback integration; engine directories separate `src/demux/`, `src/decode/`, `src/pipeline/`, `src/presentation/`, and `src/audio/`. The Jellyfin host lives in `jellyfin-webgpu-client/src/`; the independent sandbox is a separate host. [architecture.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/architecture.md)
- Native WebCodecs is preferred. Runtime-supplied `.wasm` packages carry manifests; **video packages contain WGSL GPU decode code**, optionally with a WASM parser, while audio packages decode to PCM in WASM. The pinned set includes HEVC, AV1, MPEG-2, MPEG-4, VC-1 and JPEG 2000 video, plus E-AC-3, DTS, TrueHD and WMA audio. Support is profile-specific; the format matrix also describes WebCodecs H.264 and VP9. [decoder-packages.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/decoder-packages.md), [pinned-releases.json](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/tools/pinned-releases.json)
- Presentation accepts `VideoFrame`, raw planes, or a GPU frame pool; built-in color stages handle range, YUV matrix, transfer, gamut and output encoding. PQ/HLG HDR-to-SDR operators are Reinhard, ACES, spline and ST 2094-40. Defaults: Reinhard, 1,000-nit input peak, 100-nit output peak, 203-nit paper white, exposure 0 and desaturation 0.25. HDR10+ and Dolby Vision metadata can drive scene peak/average; ST 2094-40 can follow the HDR10+ curve. [ColorPipeline.ts](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/src/color/ColorPipeline.ts), [RenderSettings.ts](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/src/presentation/RenderSettings.ts), [codec-support.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/codec-support.md)
- Audio uses layout-aware downmix matrices, 48 kHz resampling and a lookahead limiter, then a bounded AudioWorklet PCM queue. The worklet’s render time, corrected using `getOutputTimestamp`, anchors the media clock; video selects frames against it. Native AC-3/E-AC-3 can instead use a hidden MSE audio element. [architecture.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/architecture.md), [CustomAudioDownmix.ts](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/src/audio/processing/CustomAudioDownmix.ts)

**Application to Vela**

- Adopt the host-independent engine interface, explicit route eligibility, bounded queues, audio-master clock, per-format test vectors, and observable fallback reasons. MIT color and audio code are candidates for reuse after dependency review; evaluate integration costs before importing the full engine.
- Select native playback when the actual MSE type and stream configuration are supported and its presentation is acceptable. Consider the custom path only when there is a demonstrated benefit and Vela can supply demuxed CMAF samples, timestamps, seeking and adaptive-switch handling.
- Probe the **exact** codec/profile, bit depth, chroma, resolution, transfer and presentation route—not just API existence. Check `VideoDecoder.isConfigSupported`, WebGPU adapter/device limits and required features, audio output, and a small representative decode/render vector; use observed failures and dropped frames to fall back to native playback or server transcoding.
- Avoid assuming WebGPU means HDR correctness or hardware-speed decoding: the project documents 8-bit external-texture sampling on Chrome, format-specific restrictions, GPU buffer limits and software fallback costs. Test real target devices, long playback, seeks, ABR changes, power use, and audio sync before enabling a custom path by default. [codec-support.md](https://github.com/alchemyyy/WebGPU-Player/blob/a950fbf5b99b6f247314f4ed7e874fc80d99a597/docs/src/codec-support.md)

The repositories were inspected at commits `a950fbf` and `ac2cca2`; this is source research, not a runtime or device validation.
